# PCI Companion

A private preparation workspace for a merchant using multiple payment providers and payment channels. This first version explains preparation questions, reuses checked facts as draft suggestions, records supporting references and exports working answers for human review.

It does not certify compliance, determine the accepted SAQ, perform security scans, automatically read PDFs, or log in to/submit answers in a payment-provider portal. Real portal automation needs the actual provider/form and an approved mapping. The starter questions are original preparation prompts, not a complete official SAQ or a substitute for one.

## Use it

1. Enter and check the business profile, then save it.
2. Add each payment provider. Select all of its channels. Record the questionnaire and scope only after confirmation from the acquirer, including a supporting reference.
3. Open Guided questions. Reused business details and recorded scope confirmations appear as draft suggestions; explicitly review/apply them. Other questions start unanswered. Record what you actually checked, or choose Not sure.
4. Record evidence references. No files or attachments are uploaded. Do not enter card numbers, CVV, passwords, portal credentials or secret keys. Basic possible-card-data detection is a guardrail, not a guarantee that sensitive data can be identified.
5. Add the provider’s actual questionnaire using its exact questions, title, version and HTTPS source link, or import a structured JSON question pack. A sample schema is supplied at questionnaire-example.json. Importing a different form clears existing answers after confirmation; the app never silently maps answers to new questions.
6. Use Review & export to see open actions, export draft CSV answers, print/save a draft PDF through the browser, or save a JSON workspace backup. CSV exports include both providers, business details, question wording, answer, evidence, reviewer and date. Nothing is automatically sent to a provider.

Unknown responses remain open. No creates an action. Not applicable requires a reason. Missing evidence is flagged. Even a fully answered checklist remains a draft for review; it does not produce a PCI certificate or automatic attestation.

## Storage and privacy

Records stay in this browser’s localStorage under this website’s origin. They are not stored in Counter’s database, synchronised between devices or backed up by the VPS. There are no external AI calls, analytics, tracking scripts or payment-provider connections. Official links open external pages when you choose them; they do not include your answers.

Use a dedicated trusted browser profile. Anyone with access to that browser profile may access its records. Browser-local storage and exported backups are not application-encrypted. Avoid putting sensitive security details in free-text notes; reference a secure evidence repository instead. Export and protect your backup files. Private browsing, clearing site data or changing the scheme/domain/port can make a workspace unavailable; use the backup import to transfer it. Import replaces the current workspace after confirmation. Unsupported/corrupt saved data is left intact until you explicitly choose recovery or a new workspace.

This is a single-merchant, browser-local tool. Separate provider records do not create separate user accounts or tenant isolation. Multi-user access, server-side storage, audit retention and centrally managed access would be additional backend work before offering this as a shared commercial service.

## Upload to your ScalaHosting VPS

This website is static. Apache/SPanel can serve it without an additional Node process, new application port, PostgreSQL database, Docker or paid AI service. Build on the development computer, then upload only the compiled website files. Do not run the Vite development server on the VPS.

1. Create a NEW dedicated subdomain and document root in the intended SPanel hosting account. Keep it separate from Counter and the API; do not extract this package into either existing application directory.
2. Upload/extract the CONTENTS of pci-companion-vps.zip into that new document root, including the .htaccess file. The archive contains only the compiled public website.
3. Enable and verify HTTPS using SPanel. Before real use, protect the site with SPanel’s directory-password protection or an equivalent authenticated access layer. This app does not provide its own sign-in. A hidden address and noindex are not access control.
4. Merge the supplied .htaccess security headers with any authentication configuration generated by SPanel. Do not overwrite existing authentication directives. Ask ScalaHosting to help if headers or directory protection are managed centrally.
5. Verify the site in a browser: save a business profile, add two providers, answer questions, reload and check persistence, export/import a backup and open the CSV. Test PDF printing in the browser you will use. Review the scope and exact questionnaire against your acquirer’s current requirements.
6. After an update, retain the same HTTPS origin to retain browser-local data. Back up your workspace before replacing static files. For rollback, keep the previous public files; do not clear browser data.

The build assumes the dedicated domain’s document root, not a subdirectory. No production hosting configuration or provider portal has been changed by this local work.

## Develop and check

Node 24 is the development target. From this folder:

```text
npm ci
npm test
npm run dev
npm run build
```

The dev preview is http://127.0.0.1:5187/. The production output is dist/. Tests cover conservative scope hints, suggestions from checked facts, review blockers, question-pack validation, backup validation, possible-card-data detection and CSV formula neutralisation. Browser QA uses fictional records only.

## Source basis and maintenance

The questionnaire accepted for your environment is determined by your compliance-accepting entity. Always verify current eligibility and form revisions with your acquirer. Provider evidence and terminal branding alone do not establish your own compliance. These links support the workspace’s preparation guidance:

- [PCI SSC: determining the appropriate SAQ](https://www.pcisecuritystandards.org/faqs/1133/)
- [PCI SSC: SAQ eligibility criteria and scope](https://www.pcisecuritystandards.org/faqs/1443/)
- [PCI SSC document library](https://www.pcisecuritystandards.org/document_library/)

Eligibility guidance was checked during development on 4 November 2026. The software does not automatically fetch, version or update official questionnaires. Add the current form accepted by your provider and recheck imported wording before every assessment.
